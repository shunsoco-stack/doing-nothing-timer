# セキュリティとデータの扱い

## 保存と共有

- 計測記録は利用中のブラウザーの localStorage に保存します。アカウント・データベース・外部の有料APIは使用しません。
- 記録のクラウド同期やバックアップはありません。ブラウザーのデータ削除や端末の変更で記録を失うことがあるため、必要な記録はCSVで保存してください。
- localStorage は暗号化された保管庫ではありません。同じブラウザーを使える人や、同一オリジン上のスクリプトから参照・変更できます。機密情報の保管には使わないでください。
- 結果共有とCSVの作成は、利用者がそれぞれのボタンを押したときだけ行います。共有先への最終送信は利用者が選択します。
- Vercel Analytics は開始・終了・実績解除・共有の利用状況を計測するSDKを実装しています。終了理由、打鍵内容、記録ID・利用者ID、正確な日時、記録一覧は送信しません。DNT／GPCが有効な場合はイベント送信を抑止し、ページビューのURLからクエリー・フラグメントを除去します。ネットワークがない場合や解析が遮断されている場合も、タイマーは利用できます。
- 基本Web Analyticsの有効化は所有者本人の確認操作待ちです。また、Hobbyプランではカスタムイベントの集計は利用できません。SDK実装と実際の収集・集計は区別しています。詳細は [README](../README.md#analytics)、確認状況は [verification.md](verification.md) を参照してください。

## HTTPヘッダー

`next.config.ts` で以下を設定しています。

- MIME型の推測を防ぐ `X-Content-Type-Options: nosniff`
- iframe埋め込みを禁止する `X-Frame-Options: DENY` と CSP `frame-ancestors 'none'`
- 別オリジンへの参照元情報を制限する `Referrer-Policy: strict-origin-when-cross-origin`
- カメラ・マイク・位置情報を無効化し、同一オリジンの結果共有を許可する `Permissions-Policy`
- 原則同一オリジンに制限した Content Security Policy。Vercel Analytics の必要な配信元を許可しています。

静的なNext.jsの初期描画とオフライン表示に合わせ、CSPではインラインスクリプト・インラインスタイルを許可しています。nonceを使った厳格なCSPではなく、XSSを完全に防ぐものではありません。`unsafe-eval` は開発時だけ許可しています。HTMLに未検証の文字列を直接挿入しない実装を維持してください。

## PWA・オフラインキャッシュ

- Service Worker はHTTPSなどのセキュアなコンテキストの本番ビルドだけで登録します。開発サーバーでは登録しません。
- 初回のオンライン訪問時に、トップページ、manifest、アイコン、HTMLに含まれるNext.jsのJS/CSS、およびCSSから参照される同一オリジンのビルド用アセットを保存します。インストール完了前や容量不足の場合、オフライン起動できないことがあります。
- 初回ページがまだService Workerに制御されていなくても、インストール時に必要なアセットを取得します。ページ更新時は、必要なアセットの保存がすべて成功した後でキャッシュ済みHTMLを更新します。
- キャッシュ対象はトップページと許可した静的アセットだけです。RSCレスポンス、他オリジン、GET以外の通信、Analytics、CSVや共有データはキャッシュしません。
- 更新時に `skipWaiting`、`clients.claim`、強制リロードを実行しません。開いているタブの計測を中断せず、ブラウザーの通常のライフサイクルに従って新しいService Workerを適用します。更新を確実に反映したいときは、記録を終了してアプリのタブをすべて閉じ、オンラインで再度開いてください。
- 旧キャッシュの削除対象は `doing-nothing-timer-` で始まる本アプリのキャッシュだけです。localStorage の記録はService Workerの更新で削除しません。

### オフラインの確認方法

1. `npm run build` と `npm start`、または公開URLで本番アプリを開きます。
2. オンラインで初期画面を開き、Service Workerのインストール完了を待ちます。
3. 開発者ツールでオフラインに切り替えて再読み込みします。
4. ゆるモードで計測を開始・終了し、再読み込みして保存した記録を確認します。
5. オンラインへ戻します。厳格モード中のタブ切り替えは終了操作として扱われるため、オフライン確認はゆるモードで行ってください。

## Secret Scan

```sh
npm run secret-scan
node scripts/secret-scan.mjs --self-test
```

外部サービスへソースコードを送らないNode.js製のスキャナーです。Gitの追跡状態にかかわらず本プロジェクト内のテキストを検査するので、新規ファイルや `.env` も検査対象になります。秘密鍵、主要プロバイダーのトークン形式、認証情報を含むURL、秘密情報らしい名前へのハードコードされた値を検知します。ルールの自己テストを毎回実行し、検知時はファイル名・行番号・ルール名だけを表示します。値やソース行そのものはログに出しません。

除外対象は依存パッケージ、`.git`、`.next`、`.vercel`、ビルド・テスト成果物、`public/screenshots/`、シンボリックリンク、バイナリ、5MiBを超えるファイルです。依存ロックファイルは除外しません。これは既知の形式を用いる簡易検査であり、未知の形式・短いパスワード・Gitの過去履歴まで保証するものではありません。公開前に差分とファイル一覧を人が確認し、GitHub側のSecret scanningも併用してください。

`.github/workflows/ci.yml` は公式ActionsをコミットSHAで固定し、権限をソース読み取りのみにして、lint・型検査・テスト・Secret Scan・ビルドを実行する設定です。この文書自体は、実行済みの検証結果や脆弱性ゼロを保証する報告書ではありません。

## 制約

本アプリは「何もしない」を楽しむための個人向けツールです。記録は端末時計とブラウザー操作に依存し、改ざん防止・競技の公正性・健康効果を保証しません。ブラウザー外での行動や、OSがイベントを送らない状況までは検出できません。
